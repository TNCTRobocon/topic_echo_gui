# topic_echo_gui

Qt 5 + C++17で実装したROS 2 Topic Echo GUIです。

## 主な機能

- ROS 2グラフ上のTopicを一覧表示
- Topic名またはメッセージ型で絞り込み
- 表示領域を手動で左右・上下に分割し、表示枠をクリックしてトピックを割り当て
- 1つの表示枠内をTopic数に応じて自動グリッド分割し、各Topicを独立した表示領域に表示
- 1つのTopicは必ず1つの表示枠だけに所属し、別の表示枠で名前またはチェック部分をクリックすると割り当て先を自動移動
- 各Topicの表示領域はテキスト履歴とグラフを同じ領域に保持し、GUI上部の表示方式ボタンで一括切り替え
- Topic一覧のチェックマークは割り当て状態を示し、チェック部分をクリックするとTopic名のクリックと同じ割り当て・解除・移動処理を行う
- 「echo開始」で全表示枠に割り当てられたTopicを購読開始
- Echo中にTopicを表示枠へ割り当てると、そのTopicの購読を開始。すでに購読中のTopicを別枠へ移動しても購読を作り直さない
- 「echo停止」で全購読を解除
- 「すべて選択解除」で全表示枠からTopic割り当てを解除
- 分割位置をドラッグで調整し、表示枠の削除にも対応
- 分割構造、分割比率、表示枠ごとのTopic割り当てを `~/.config/topic_echo_gui/settings.json` に保存し、次回起動時に復元
- 旧設定の「1表示枠につき1Topic」形式も読み込み可能。重複して割り当てられている設定は最初に見つかった表示枠を優先して整理
- 設定を復元しても購読は自動開始せず、「echo開始」を押して開始
- 実行時に型を読み込むGeneric Subscriptionに対応
- `/joy` は `sensor_msgs/msg/Joy` の型付き購読で表示
- Topicごとに直近2000件のメッセージ履歴と数値データを保持し、テキスト表示では過去方向へスクロール可能
- GUI更新は2ms間隔を基本とし、受信と画面更新を分離
- グラフはメッセージ型の数値フィールドを動的に抽出し、複数ある場合のみTopicごとの選択欄を表示。数値フィールドが1つなら自動選択

## ビルド

```bash
cd ~/ros2_ws
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-select topic_echo_gui
source install/setup.bash
```

## 実行

```bash
ros2 run topic_echo_gui topic_echo_gui
```

通常は ROS_DOMAIN_ID を必要な値に設定してから起動してください。

## 操作

1. 起動時にTopic一覧を自動取得します。「更新」を押すと再取得できます。
2. 表示したいTopicの名前またはチェック部分をクリックします。どちらも同じ操作で、未割り当てなら選択中の表示枠に割り当て、同じ枠に割り当て済みなら解除し、ほかの枠に割り当て済みなら選択中の表示枠へ移動します。
3. 表示枠内のどこかをクリックして割り当て先を選びます。「左右に分割」または「上下に分割」で、選択中の表示枠を分割できます。
4. 「echo開始」を押すと、表示枠に割り当てられたTopicの購読を開始します。Echo中に割り当てを追加すると、そのTopicも購読します。
5. Topic一覧のチェックマークは、そのTopicがどこかの表示枠に割り当てられているかを示します。チェック部分をクリックするとTopic名をクリックした場合と同じ操作を行います。Echo停止中でも、割り当てられているTopicにはチェックが付きます。
6. 「echo停止」で購読をすべて解除します。表示枠への割り当ては保持され、再度「echo開始」を押すと購読を再開します。
7. 「すべて選択解除」で全表示枠からTopicの割り当てを解除します。Echo中の場合、これに伴い購読も解除されます。
8. 表示枠の境界をドラッグすると分割比率を調整できます。「削除」で選択した枠を削除できます。最後の1枠は削除されず、Topic割り当てだけが解除されます。
9. 「表示方式：テキスト／グラフ」で全Topicの表示方式を一括切り替えできます。グラフ表示時、数値フィールドが複数あるTopicにはフィールド選択欄が表示されます。
10. 各Topicのテキスト履歴は独立してスクロールできます。最下部を表示しているときだけ新着データへ自動追従し、上へスクロールしている間は閲覧位置を維持します。
11. 「表示クリア」で全Topicのテキスト履歴とグラフ履歴を消去します。「echo停止」では履歴を保持します。
12. 設定は変更時に保存され、次回起動時に分割構造、分割比率、Topic割り当てが復元されます。購読自体は自動開始されません。

## QoS

購読は BEST_EFFORT / VOLATILE / KEEP_LAST(10) を使用します。

## 表示方式

`/joy` はC++の `sensor_msgs::msg::Joy` を直接受信して文字列化します。
その他のTopicはROS 2のGeneric Subscriptionと型サポートを使って実行時にデシリアライズします。

ROS 2の受信コールバックでは履歴キューへデータを追加するだけにし、GUI側のタイマーでまとめて反映します。
各Topicは直近2000メッセージ、または履歴データ概算16 MiBまでを保持します（どちらか先に到達した方を適用し、最新の1件は保持します）。テキスト表示では最下部を表示中の場合だけ自動スクロールし、過去へスクロールしている場合は閲覧位置を維持します。
各メッセージから最大128個の数値フィールドを抽出し、グラフはフィールドごとに直近2000点を保持します。数値フィールドが複数ある場合の選択欄はグラフ表示時のみ現れ、1つなら自動選択、0個ならグラフ化できない旨を表示します。
GUI上部の「表示方式：テキスト／グラフ」で全Topicの表示方式を一括切り替えできます。テキストとグラフは同一のQStackedWidget領域を共有します。
「表示クリア」はテキスト履歴とグラフ履歴を全Topicまとめて消去します。「echo停止」は受信を止めますが、表示済みの履歴は保持します。

Python版の `main.py` / `setup.py` / `setup.cfg` は削除済みです。 `package.xml` のbuild typeは `ament_cmake` で、`ros2 run topic_echo_gui topic_echo_gui` はC++実行ファイルを起動します。
